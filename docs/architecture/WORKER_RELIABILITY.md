# Worker reliability

Run `python -m app.jobs.worker` from backend with its virtualenv active, or use the Compose worker service. One process runs one bounded job at a time. Multiple processes share PostgreSQL limits: four globally, one per tenant. A brief common advisory lock serializes capacity decisions; SKIP LOCKED claims one oldest eligible row. One busy tenant cannot occupy all global slots. Dead workers temporarily occupy a slot until expiry reconciliation. No transaction stays open during polling or backoff sleeps.

Claims increment a fencing token, persist owner/heartbeat/30-second expiry and create an attempt. The worker marks RUNNING before calling ControlledActionExecutor. Its internal identity references the persisted actor, original non-secret session ID, job ID, owner and fence. HTTP authentication never constructs this capability. Current active User and action:execute permission are required independently of submitter cookie expiry/logout. Existing independent reviewer session/grant validation is unchanged.

The executor locks the job and live actor inside its existing SERIALIZABLE transaction, validates capability and canonical binding, then reruns policy/evidence/resource/approval validation. Its optimistic resource update is bounded by the minimum policy/approval/lease deadline. The job lock prevents takeover/cancellation during mutation; fencing rejects stale workers before mutation. Existing receipt/proposal uniqueness prevents duplicate effects even if two execution callers race. The 30-second lease exceeds the local executor's bounded SQL windows; no background renewal thread extends stalled execution. Heartbeat records claim/start checkpoints. Longer external operations are outside this phase.

SIGTERM/SIGINT stops further claims and allows current bounded processing to finish. Compose gives 40 seconds before termination. A killed process leaves durable state for reconciliation. A process-local PostgreSQL circuit breaker opens after three database failures for 15 seconds, allows one half-open probe, and resets after success. Persistent DB outage cannot be written to an unavailable DB; the lease remains the recovery signal. Breakers do not grant permissions or skip policy checks.

Structured logs contain job/tenant/correlation IDs and categories only. Worker snapshots report state totals, queue age, mean attempt latency, retry/dead-letter/reconciliation counts, lease expirations and duplicate submission prevention from durable metadata. Transition log lines can precede a failed commit; persisted events are the source of truth. These are local operational metrics, not a production monitoring service.
