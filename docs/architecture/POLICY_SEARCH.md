# Deterministic policy search

Migration `0005_policy_applicability` adds category, resource type, effective/expiry timestamps, allowed account states and scenarios. Existing synthetic rows receive deterministic metadata. Reactivation v1 has an expired effective window; v2 remains current. Seeds insert missing rows only and preserve operator changes. No new business records or customer data are required.

`search_policy` retains its existing registry name/version, permission, executor and strict bounded contract. Optional metadata fields preserve validation of old checkpoints. Query length is 2–240 characters; normalization lowercases ASCII words of 2–32 characters, deduplicates/sorts and takes at most eight. SQLAlchemy binds values; no source or query text becomes SQL syntax. Nonmatching queries return an empty collection.

Search predicates require the trusted tenant and an effective window (`effective_at <= database current time`, `expires_at IS NULL OR expires_at > current time`). A correlated tenant/key query excludes a version only when a higher version is itself currently effective. Future or expired high versions never suppress a current lower version. Policies are ranked by key keyword count, then key/description keyword count, version descending, UUID ascending. Result size is 1–20. Future, expired and superseded versions are excluded from this current-policy tool; it is not a historical policy browser. Current rows carry `policy_status=current`; legacy payloads without dates carry `unknown`.

Canonical policy provenance includes exact policy UUID/version, dates, category, resource type, states and scenarios. With observed account/ticket context, retrieval metadata records a nullable applicability suggestion, account state/scenario and `authorization=not_evaluated`. A suggestion requires a current account policy with matching state and scenario; unknown context is not a positive match. Ranking does not certify eligibility. Phase 7 owns deterministic action eligibility; no Phase 7 code is implemented here.

Limitations: keyword search has no synonyms, semantic embeddings or unrestricted full-text retrieval. It searches descriptions as untrusted evidence but drops their prose before canonicalization. Applicability lists are operational metadata, not a policy interpreter. Equal-key effective versions use explicit version precedence; inconsistent observations from separate executions are surfaced by reconciliation. Changes after collection require later-phase revalidation, not an assertion of current authorization.
