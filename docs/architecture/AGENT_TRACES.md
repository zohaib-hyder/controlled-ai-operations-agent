# Operational agent traces

The existing authenticated investigation result exposes additive `tool_selection_trace`, `iteration_count` and `execution_limits`, alongside existing planner type/version, counters, state, stop reason, evidence and reconciliation. Existing endpoints, tenant/creator ownership and CSRF rules are unchanged. Old records expose empty traces/default optional fields and remain readable. Events/evidence pagination remains bounded; a trace itself has a fixed 64-entry schema bound.

Each trace entry contains iteration, decision type, concise backend-generated summary, selected tool and step ID, SHA256 of canonical sorted JSON arguments, tool execution ID, observation envelope ID, canonical source evidence IDs, validation outcome, consumed budget counters, stop reason and actual timestamp. Tool completion/failure and terminal decisions have trace records. STOP is a backend terminal marker, never a fifth accepted planner proposal. Pre-dispatch decisions are also durably represented by the existing step definition and `tool_execution_started` event with type/iteration/arguments hash; no duplicate trace row is needed for the same call. A process loss between dispatch boundaries therefore remains visible as a proposed step, not fake completed progress.

Checkpoint trace prefixes cannot be rewritten by normal repository saves. Final trace lives in both the durable checkpoint and terminal result and must agree on reads. Execution source links continue to use the existing tenant-aware evidence and tool-execution foreign keys. Hashes are stable for the same arguments; they are not external audit attestations. Database-owner tampering remains outside the ORM append-only protection boundary.

The frontend labels deterministic mock versus optional real LLM, shows actual iterations/call usage, decision selections, executed/failed status, source links, review/stop state and provider reservations when applicable. Existing step purpose/expected-evidence data is a bounded operational description; it is not proof that an action is authorized. Canonical observed facts and provider proposals remain distinct. No private chain-of-thought, unrestricted reasoning transcript, fake progress or confidence percentage is stored or displayed.

On revoked authorization, lease loss or unavailable persistence, the executor withholds successful finalization. A later authorized reader sees the last committed trace/checkpoint and can use conservative recovery. There is no bypass that writes history under a revoked actor just to create a terminal success. Corrupt checkpoints fail closed; earlier append-only lifecycle events and independently stored evidence remain available. Records have no new automatic retention or distributed worker infrastructure in Phase 6.
