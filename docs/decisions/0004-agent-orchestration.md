# 0004: Request-scoped read-only investigation orchestration

Phase 3 integration audit: existing ToolExecutor validates the live session, permissions, strict tool schemas and tenant ownership, and persists metadata independently. Identity and tenant repositories are frozen. The authentication dependency resolves the session before API admission. Frontend uses a fixed-route same-origin proxy and permission-aware shell. Existing fixture databases support independent worker sessions.

Decision before implementation: reuse ToolExecutor directly for every evidence read. Bootstrap customer and customer-ticket reads establish resource membership; account IDs are selected only from that customer's validated ticket results. Optional tickets must occur in that bounded list, otherwise stop for review. A provider-neutral asynchronous planner emits strict typed steps and advisory interpretations. Backend validates step schemas, permissions and investigation resource scope separately from planner intent. Findings are rendered by deterministic backend logic from observed structured fields, never from instruction-bearing text.

Use a finite explicit state machine and server-configured budgets. No durable background tasks or schema changes. A bounded expiring process-local result store binds tenant and actor; GET reauthenticates and requires investigation:create. Results disappear on restart and are not shared across workers. Tool execution metadata remains durable; this is not checkpoint recovery. Cancellation drains existing ToolExecutor work and stores a terminal cancellation result when possible. No writes, approval decisions or eligibility certification are introduced.
