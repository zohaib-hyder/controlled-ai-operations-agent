# 0005: Durable investigations and conservative lease recovery

Audit before implementation: Phase 3 keeps a bounded OrderedDict of terminal results, executes request-scoped, and uses frozen contracts/state transitions. ToolExecutor already revalidates live sessions, read permissions and investigation:create, with separate durable tool audit transactions. Evidence is provenance-bearing; source prose is untrusted. Existing tenant repositories and API use server-derived identity and composite FKs. Frontend proxy is a fixed allowlist and workspace currently loses its result on refresh.

Replace the OrderedDict with five PostgreSQL tables and one repository owning all lifecycle writes. Bind history to tenant plus creating actor, preserving Phase 3 privacy. Revalidate the current session/role on repository operations. Validate customer/ticket ownership before creation; foreign references now return a safe HTTP 404 rather than persisting an invalid foreign reference. Use an actor/tenant/key unique constraint and canonical payload hash for idempotency. Missing keys receive a fresh UUID for compatibility; the UI supplies keys.

Versioned bounded checkpoint snapshots retain counters, strict plans, minimal structured observations and evidence references, omitting source prose and session secrets. Row locks plus expected version checks serialize events/checkpoints and state transitions. Metadata mutations, step/evidence/event inserts and checkpoint save commit together. Tool execution remains outside these transactions; before-tool and after-observation commits expose ambiguity explicitly.

A random owner UUID, database-time lease and fenced writes prevent concurrent acquisition. Heartbeat renews while async work is pending. Recovery is an explicit authenticated owner-only POST, never automatic background replay. Expired leases are required. Restore validated checkpoints/counters and charge elapsed downtime conservatively. Never replay an in-flight step: finalize NEEDS_REVIEW. Corrupt checkpoints fail closed. Terminal states never restart. Read-only tools do not imply a distributed exactly-once guarantee. No broker, distributed worker framework, business-changing tools or approval execution.
