# Phase 9 reliability evaluation

The deterministic PostgreSQL matrix exercises five existing controlled actions across eleven conditions (five normal controls plus 50 injected-failure scenarios): normal execution, lease loss before execution, crash before execution, crash after commit/before response, expired submitter session, current role revocation, operational policy change, resource change, cancellation, real PostgreSQL SQLSTATE 40001 rollback, and retry exhaustion. Every scenario creates a real investigation, proposal and decision; restricted actions obtain independent reviewer approval. Business writes use ControlledActionExecutor.

Machine-readable assertion-backed cases are in [phase9-results.json](phase9-results.json), generated by `scripts/aggregate_phase9_eval.py`. The aggregator refuses incomplete or duplicate scenario sets. Each negative case compares full business snapshots across both tenants after explicit fixture preparation. Positive cases verify the single immutable execution receipt and expected note/request count. Existing executor tests independently verify protected resource fields, exact outcomes and rollback.

| Measure | Observed |
| --- | --- |
| Safe expected outcomes | 55/55 |
| Safe recovery (pre-execution crash, post-commit crash, lease expiry, serialization) | 20/20 |
| Reconciliation correctness (crash and lease cases) | 15/15 |
| Retry classification (serialization and exhaustion) | 10/10 |
| Dead-letter correctness | 5/5 |
| Cancellation correctness | 5/5 |
| Role/resource change blocking | 10/10 |
| Duplicate mutation cases | 0/55 |
| Unauthorized mutation cases | 0/55 |

Operational policy changes block all three policy-bound restricted actions (3/3). The two note actions have no dynamic operational policy binding; unrelated policy edits correctly leave them eligible (2/2). Submitter cookie expiry does not revoke durable work (5/5); active user/current permission and reviewer grant checks remain mandatory.

Additional integration cases cover approval expiry, concurrent claims, fencing, cooperative cancellation, lost response after actual commit, ambiguous consumed approval without a receipt, manual retry, original retry-window exhaustion, capacity, strict scheduling attributes, submission throttling and tenant isolation. Foreign-job probes include three GET routes and two POST routes, all 404, with an empty foreign-tenant queue: leakage 0/5 probed job routes. These route probes are separate from the 55-case business matrix.

The database outage test opens a real refused local PostgreSQL connection and tests breaker open/half-open/recovery. Commit-response loss is injected after the actual controlled transaction commits. Crash hooks are internal test parameters, never API controls. SQL serialization faults are raised by PostgreSQL; worker repository methods are not mocked to return success. Test/live retry timestamps are explicitly advanced as synthetic fixtures, without reducing production backoff or bypassing current security checks.

Live authenticated A–J evidence is retained in [phase9-live-verification.json](../phases/assets/phase9-live-verification.json). No external provider, paid call or real customer system is involved. Local synthetic reliability evidence does not establish production readiness or exactly-once external effects. Final command counts and known failures are recorded in the phase report.
