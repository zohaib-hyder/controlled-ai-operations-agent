# Test stability

The Phase 11 evidence is preserved in `docs/evaluations/PHASE_11_STABILITY.md`: five targeted repetitions (25 passes), 52 reverse-order execution cases and three successful full runs (702, 706, 710 tests). It also preserves the intentionally aborted run. The historical Phase 10 three 409 eligibility failures have no proven root cause; no Phase 12 documentation reclassifies them as fixed.

The exclusive PostgreSQL fixture lock prevents simultaneous destructive suites against the same `_test` database. It does not prevent CPU/memory contention from unrelated builds or workers. Phase 12 uses serial heavy acceptance stages, no browser retries, fresh per-project release records and bounded event/poll waits. The old cancellation cohort requires an explicitly stopped worker. The active-worker cohort runs separately after worker startup. Do not concurrently refresh policies used by a pending approval.

Fresh Phase 12 run results and any failures are recorded in PHASE_12 and its machine evidence, not inferred from prior phases. Repeated full-suite, reverse-order and repeated browser evidence must be separately identified. A successful rerun never erases the first failure.

Phase 12 measured a distinct authentication connection-lifetime bottleneck at 20 clients and fixed that narrow issue, with a real one-connection-pool regression. This is not proof of the historical eligibility failure cause. The first full Phase 12 cohort passed 720 tests before final additions. A later 723-test cohort passed 722 with one `missing_policy` result of BUDGET_EXCEEDED/wall_clock_limit instead of NEEDS_REVIEW/missing_evidence (22.043-second call, six authorized tools, no mutation/leakage). Five exact predetermined repeats then passed with investigation durations 596–673 ms and the same eight-second limit. Added diagnostic fields record investigation duration and tool names/outcomes/timings without evidence payloads. The failure remains unresolved; after-failure host/container snapshots cannot establish causality. Final fresh cohort results are recorded in PHASE_12.

The final coordinator passed all 723 backend tests (743.41 seconds) and all 601 catalog scenarios. Its default browser cohort passed 52/52, positive primary/isolated cohorts 4/4 each, and isolated negative cohort 8/8, without retries or skips. A separate fresh default repeat then passed 51 and failed the mobile auditor-to-foreign-admin sign-in transition. That test did not await logout before navigating to login. It now explicitly waits for the actual logout response, sign-in screen and server 401 before signing in as another actor. No app/session authorization behavior changed.
